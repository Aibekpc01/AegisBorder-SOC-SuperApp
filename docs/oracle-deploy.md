# AegisBorder на Oracle Cloud Always Free

Этот вариант запускает весь проект на виртуальной машине: React, FastAPI, PostgreSQL, вход, личные сценарии, документы и чат. Компьютер разработчика не нужен после установки. Главная открывается по `/`, рабочая панель — по `/app`. Конфигурация подготовлена и проверена локально; VM в аккаунте пользователя ещё не создана.

## 1. Аккаунт и бесплатная VM

Откройте [Oracle Cloud Free Tier](https://www.oracle.com/cloud/free/) и зарегистрируйтесь. Проверку личности и платёжного средства проходите самостоятельно в Oracle; не отправляйте реквизиты в чат.

В Home Region откройте Compute → Instances → Create instance:

| Параметр | Значение |
|---|---|
| Name | aegisborder |
| Image | Ubuntu, с бесплатной лицензией |
| Shape | VM.Standard.A1.Flex / Ampere ARM |
| OCPU / Memory | 2 OCPU, 6 GB; сверить общую квоту аккаунта |
| Boot volume | 50 GB; проверить суммарный объём всех дисков |
| Networking | Публичная подсеть, публичный IPv4 |
| SSH | Собственный ключ; приватный файл хранить только у себя |

На дату подготовки текущая документация указывает 2 OCPU / 12 GB суммарно для A1 Always Free и 200 GB дисков суммарно. Ориентируйтесь на Always Free eligibility и квоты своей Console. При нехватке capacity попробуйте другой Availability Domain внутри Home Region; платную shape автоматически не выбирайте. Источник: [Always Free Resources](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm).

В Security List или NSG разрешите TCP 80 и 443 для посетителей, TCP 22 только со своего административного IP. Отдельно проверьте firewall Ubuntu. PostgreSQL 5432 и приложение 8000 в Интернет не открываются. Создание VM в этом проекте не автоматизировано, чтобы случайно не выделить платный ресурс.

## 2. Исходники и Docker

После создания VM понадобятся публичный IP и локальный путь к SSH-ключу. Подключение для Ubuntu:

```powershell
ssh -i "C:\путь\к\ключу.key" ubuntu@ПУБЛИЧНЫЙ_IP
```

На сервере установите Docker Engine с Compose по [официальной инструкции для Ubuntu](https://docs.docker.com/engine/install/ubuntu/). Docker должен запускаться при загрузке ОС. Исходники находятся в приватном репозитории `Aibekpc01/aegisborder`: можно передать подготовленный архив по SCP и распаковать или клонировать с разрешённым GitHub-доступом. Пароли и ключи не включайте в URL clone.

Dockerfile собирает frontend на сервере. Образы Node, Python, PostgreSQL и Caddy должны поддерживать ARM64; конфигурация также пригодна для AMD64. Установка на реальном ARM-сервере ещё должна пройти проверку.

## 3. Адрес и секреты

Для собственного домена создайте DNS A-запись на публичный IP VM. Если домена пока нет, можно отдельно выбрать DNS-поддомен; публичный IP сам по себе не создаёт имя `aegisborder`. HTTPS выпускается Caddy после настройки DNS и открытия портов 80/443.

На сервере, из каталога проекта:

```bash
python3 scripts/create_oracle_env.py --domain ВАШ_DNS_АДРЕС
sudo docker compose -p aegis-oracle --env-file .env.oracle -f compose.oracle.yaml up -d --build --wait --wait-timeout 240
```

Скрипт создаёт случайные DB_PASSWORD, ADMIN_PASSWORD и AUDIT_KEY в `.env.oracle`, с правами 600 на Linux. Значения не печатает и существующий файл не заменяет. `.env.oracle` исключён из Git и Docker build context. Для входа администратора получите ADMIN_PASSWORD непосредственно на своём сервере, не публикуйте его. Посетители нажимают «Попробовать без регистрации» и получают отдельные demo-сеансы.

Caddy хранит сертификаты в отдельном томе, перенаправляет HTTP на HTTPS и передаёт WebSocket. Приложение доверяет forwarded-IP только конкретному адресу Caddy `10.88.7.10`. Перед установкой убедитесь, что подсеть `10.88.7.0/24` не конфликтует с существующими Docker-сетями. PUBLIC_ORIGIN задаётся по вашему DNS-имени; Secure-cookie включается автоматически.

## 4. Проверка и резервная копия

```bash
sudo docker compose -p aegis-oracle --env-file .env.oracle -f compose.oracle.yaml ps
curl --fail https://ВАШ_DNS_АДРЕС/api/v1/health
sudo python3 scripts/backup_oracle.py
```

Проверьте главную, вход администратора, два личных посещения, сохранение документа, сценарий и чат. После перезагрузки VM контейнеры должны запуститься благодаря Docker и `restart: unless-stopped`.

Ежедневный запуск резервной копии можно добавить через `sudo crontab -e`:

```cron
15 3 * * * cd /opt/aegisborder && /usr/bin/python3 scripts/backup_oracle.py >> /var/log/aegisborder-backup.log 2>&1
```

Укажите фактический путь установки, если это не `/opt/aegisborder`. Время cron — часовой пояс VM. Дамп создаётся в `backups`, не попадает в Git. Копируйте дампы и `.env.oracle` в отдельное защищённое хранилище; копия только на той же VM не защищает от её потери. Следите за местом и политикой хранения. AUDIT_KEY нужен для проверки прежнего журнала аудита.

При обновлении сначала создайте дамп, затем пересоберите приложение. Не используйте `down -v`: этот флаг удаляет том базы. Импорт существующей рабочей базы выполняется отдельно после проверки дампа и сохранения её AUDIT_KEY; простая публикация исходников данные не переносит.

## Ограничение постоянной работы

Always Free не имеет срока истечения, но Oracle может освобождать простаивающие VM и временно не иметь свободной capacity. Поэтому это размещение без зависимости от домашнего компьютера, а не обещание гарантированной доступности навсегда. Нужны резервные копии и контроль состояния аккаунта. Условия простоя описаны в [документации Oracle](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm).
