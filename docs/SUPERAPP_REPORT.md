# Первый рабочий этап SuperApp

14 октября 2026 года. Работа выполнена в существующем проекте и локальной ветке `feature/superapp-redesign`.

## Реализовано

- Публичный лендинг `/`: назначение платформы, интерактивный явно обозначенный пример, возможности, схема, учебные ситуации и состояние интеграций. Приватные API на нём не вызываются.
- Защищённая область `/app` с прежними функциями; новые ссылки `/app/...`, старые прямые ссылки сохранены, включая `/assets` без конфликта с каталогом сборки.
- Современная оболочка, тёмная и дополнительная светлая тема с сохранением выбора в браузере. Публичная страница и редактор загружаются отдельными JS-модулями.
- Глобальный поиск по реальным доступным событиям и инцидентам; переход к результатам в мониторинге. Список незакрытых инцидентов с обновлением, без фиктивного статуса прочтения уведомлений.
- Workspace: шаблоны, форматированный редактор Tiptap, таблицы, автосохранение PostgreSQL, поиск, версии, инцидент, ответственный, комментарии и статусы. Добавочная миграция 004, RBAC, изоляция учебных материалов, аудит, HMAC и отказ при конфликте версий.
- Сброс учебного сеанса сохраняет документы и журналирует снятие связи с удалённым учебным инцидентом.

## Проверки

Production build Docker/TypeScript/Vite проходит. Pytest: 62 теста, включая 11 новых проверок документов; Vitest: 3. Полный Playwright/Edge: 6 комплексных тестов, включая лендинг без приватных запросов, темы, мобильную ширину, сохранение текста/таблицы/заметки, утверждение, историю версий, обновление страницы, старые ссылки, поиск и прежние сценарии. ESLint и Ruff проходят. npm при установке зафиксированных зависимостей сообщил 0 известных уязвимостей.

Изолированная PostgreSQL-проверка Workspace: 16 конкурентных сохранений одной версии, одно принято, 15 получили конфликт, осталось ровно две версии; HMAC-аудит целый. Временная тестовая схема удалена, рабочие таблицы не менялись.

Миграция в действующей базе — `004_workspace (head)`. Исходные 6 событий и 1 инцидент v0.2 сохранены. Приложение и PostgreSQL healthy. Браузерные проверки используют отдельные синтетические учётные записи, отключаемые после теста; рабочий пароль администратора не менялся. Тестовые документы и аудит сохранены.

После перезапуска приложения сравнен SHA-256 полного набора текущих документов, их содержимого, версий и количества исходных записей: значение до и после одинаковое. Архив `backup-before-superapp.dump` читается `pg_restore --list` (224 строки оглавления); восстановление именно этого нового архива ещё не выполнялось. Собранный frontend скопирован в `app/web` для локального режима.

При проверках были выявлены и исправлены: ложная отметка изменений при переключении доступности Tiptap и отказ допустимому атрибуту выравнивания ячейки. Увеличение JS-сборки устранено разделением лендинга, приложения и редактора; сборка больше не сообщает превышение установленного порога размера чанка.

Снимки: `frontend/test-results/superapp-landing.png`, `superapp-light.png`, `workspace-editor.png` и прежние снимки сценариев. Проверено в установленном Microsoft Edge, не заявляется проверка всех браузеров и ОС.

## Оставшиеся этапы

Граф связей и цифровой двойник, почтовая безопасность, конструктор сценариев, задачи/согласования, реальные внешние интеграции, уведомления с журналом прочтения, дополнительные экспорты документов и совместное редактирование. В интерфейсе неготовые модули обозначены как запланированные, без кнопок имитации.

Прежние ограничения VPN/геолокации, промышленной эксплуатации и Windows 8/8.1 сохраняются; см. аудит и документацию безопасности. Нет подключения к реальной инфраструктуре.

## Запуск

Лендинг: http://127.0.0.1:8000/ ; панель: http://127.0.0.1:8000/app ; документы: http://127.0.0.1:8000/app/workspace ; комиссия: http://127.0.0.1:8000/app/commission .

При следующих запусках используйте `Запустить.bat` при работающем Docker Desktop либо `docker compose up -d --build --wait --wait-timeout 240`. Облегчённый запуск описан в `docs/installation-windows.md`.

Восстановление кода и расположение резервной копии описаны в `docs/SUPERAPP_AUDIT.md`. Этот этап не удалял таблицы, том базы, существующие миграции или пользовательские файлы.
