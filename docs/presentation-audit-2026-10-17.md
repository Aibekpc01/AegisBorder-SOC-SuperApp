# Аудит готовности AegisBorder к презентации

**Вывод: проект готов к управляемой учебной презентации с подготовленным сценарием.** Работает основной путь от события до расследования, PDF и документа. Для открытого показа предпочтительна подготовленная сборка с исправлениями этого аудита. Промышленная эксплуатация со служебными данными требует отдельной приёмки.

Проверка начата 17 октября 2026 года. Опубликованная версия — `emblems-20261017-r15`, адрес [рабочего сайта](https://aegisborder.130.61.214.154.sslip.io/app). Исправления сохранены в текущем проекте и собраны в отдельный ARM64-образ для временного проверочного контура. Рабочий сайт на этот образ не переключался.

Роль `demo_viewer` предназначена для просмотра и ограниченных тренировочных действий; редактирование расследования и документов ей запрещено. Административный показ требует подготовленного входа и выполнения назначенных требований DLP.

## Что остаётся перед открытым показом и эксплуатацией

1. **Публикация исправлений и репетиция на нужном ПК.** Основной учебный маршрут уже работает; административный браузерный сеанс может потребовать подтверждения DLP. Проверять нужно тот же браузер и устройство, которые будут подключены к проектору.
2. **Автоматические и внешние резервные копии.** В просмотренных заданиях cron/systemd не найдено резервирования приложения. Копия на той же VM не защищает от потери VM. Нужны защищённая копия вне сервера, сохранение необходимых ключей конфигурации и регулярная репетиция восстановления. Проверка этого аудита использовала действующее окружение приложения.
3. **Приватность каталога сотрудников.** Публичный гость может читать имена, роли, подразделения и присутствие сотрудников через каталог. IP других пользователей ему не выдаётся. Перед внешним показом использовать вымышленные карточки либо ограничить видимость каталога для гостей.
4. **Ограничение регистрации гостей за общим NAT.** Сохраняется намеренный лимит десяти новых тренировок за час с одного внешнего IP. Для аудитории с общим университетским адресом лучше заранее открытые сеансы или отдельный механизм приглашений. Исправление прокси не отменяет этот лимит.
5. **Защитные заголовки и контейнер.** HTTPS перенаправление 308, `nosniff`, `DENY` и `same-origin` присутствуют. CSP и HSTS в проверенном ответе отсутствуют. CSP вводить с проверкой загрузок и WebSocket; затем включать рабочую политику. Контейнер приложения сейчас запускается с пользователем по умолчанию root; перед эксплуатацией нужны отдельный непривилегированный пользователь и лимиты ресурсов.
6. **Скорость первого открытия.** Эмблема занимает около 1,4 МБ, иллюстрации — около 1,8 и 2,1 МБ. Нужны варианты по размеру, современные форматы и политика кеширования хешированных ресурсов. Мобильная главная длинная; основной показ следует вести по короткому маршруту, а не прокручивать весь каталог.
7. **API и обработка адресов.** Документация API открыта публично; это само по себе не обход доступа. Служебные и неизвестные URL могут получать оболочку приложения с HTTP 200. Для закрытого выпуска нужны осознанная политика документации, корректные служебные файлы и 404 с сохранением прежних допустимых ссылок.
8. **Windows-пилот.** Для массовой установки нужны цифровая подпись издателя, чистая установка, обновление, удаление, восстановление USB-политики, проверка разных браузеров и конфликтов с доменной политикой. Самоотчёт агента не является аппаратной аттестацией.
9. **Архитектура и длительные испытания.** `api.py` и `command-center.tsx` остаются крупными, frontend широко использует `Row/any`. Нужны постепенные DTO и разделение модулей, CI, более длительные испытания и независимый обзор безопасности.
10. **Фиксация проверенной версии.** Рабочая папка содержит изменённые и новые, ещё не отслеживаемые Git файлы, включая серверные модули и миграции. Текущий HEAD не является снимком проверенного проекта. Подготовлен отдельный архив исходников; перед следующим выпуском нужно зафиксировать выбранные код, тесты, миграции и документацию без секретов. Нативный EXE собирается отдельно в Windows; исходный архив не заменяет пакет поставки агента.

На ближайший этап полезнее повысить надёжность и ясность существующего пути, чем увеличивать количество разделов.

## Как повторить основные проверки

```powershell
.venv/Scripts/python.exe -m pytest -q
.venv/Scripts/python.exe -m ruff check app migrations scripts tests
cd frontend
npm.cmd test
npm.cmd run lint
npm.cmd run build
```

После установки обновлённого скрипта на существующий сервер его фактической конфигурации соответствует команда:

```bash
python3 scripts/backup_oracle.py --project aegisborder_soc_v02 --env-file .env --compose-file compose.yaml --compose-file compose.oracle.yaml
```

Скрипт создаёт дамп; он не заменяет отдельное защищённое хранение необходимых настроек и не выполняет восстановление поверх рабочей базы.
