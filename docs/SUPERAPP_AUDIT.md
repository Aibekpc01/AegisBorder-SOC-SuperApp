# Аудит перед AegisBorder SuperApp

Дата: 14 октября 2026 года. Исследован существующий проект, новая система с нуля не создавалась.

## Фактическое состояние

Frontend: React 19, TypeScript, Vite, Tailwind CSS 4, React Router, TanStack Query, Recharts, Lucide и компоненты на Radix. Точка входа — `frontend/src/main.tsx`; учебный полигон, визуальная инструкция, профили, сетевые ограничения и таблица событий вынесены в компоненты. Основной компонент пока крупный; последующие модули следует выделять отдельно.

Backend: `app/main.py` подключает `app/command/api.py`; FastAPI, SQLAlchemy, Pydantic, Alembic. Модули detection, analytics, reports, security, profiles и access отвечают за отдельные функции. PostgreSQL 16 в Docker — текущий основной режим; SQLite доступен для запуска без Docker. Исходная версия сохранена в `app/legacy_main.py`, `app/static/index.html` и документации.

API `/api/v1`: авторизация, главная панель, события, инциденты, расследования, активы, правила, сценарии, демонстрационные сеансы, аналитика, PDF, аудит, пользователи, профили и политика сетевого доступа. WebSocket `/api/v1/ws` передаёт изменения для обновления запросов. FastAPI отдаёт собранный React и поддерживает прямые ссылки SPA.

База: основные таблицы имеют префикс `cc_`, старые таблицы v0.2 сохранены. Миграции 001–003 неизменяемые. Есть роли, сеансы авторизации, активы, события, правила, предупреждения, инциденты и связи, комментарии, история, расследования, демонстрационные сеансы, запуски сценариев, отчёты, аудит, версии моделей, настройки, профили и история входов. Фотографии хранятся в базе после очистки и уменьшения изображения.

До модернизации существуют 14 страниц: главная панель, события, инциденты, анализ, аномалии, компьютеры, сценарии, расследования, отчёты, пользователи, аудит, настройки, помощь и комиссия. Реализованы 15 различных синтетических сценариев, корреляция, оценка риска, жизненный цикл инцидента, комментарии, расследования и сохранённые PDF. Isolation Forest отделён от правил и не сопровождается вымышленными показателями точности.

## Проверки исходной версии

Согласно предыдущим фактическим прогонам: Pytest — 51 тест, Vitest — 3, Playwright/Edge — 5 комплексных сценариев. Выполнялись ESLint, Ruff, production build, проверка PostgreSQL и конкурентной обработки. Подробности и ограничения: `docs/testing-results.md`. При начале этого этапа контейнеры приложения и базы были healthy, сайт опубликован только на 127.0.0.1:8000. Версии окружения: Node 24.21.0, Python локально 3.14.7, Git 2.56.0; Docker использует Python 3.12.

## Выявленные ограничения

- Публичного лендинга и отдельного адреса `/app` пока нет.
- Нет документов Workspace, их версий, согласований и задач; для них нужны отдельные модели, миграции и API с проверкой доступа.
- Почтовая безопасность, цифровой двойник и конструктор сценариев не реализованы. Показывать их как действующие функции нельзя.
- Нет глобального поиска по нескольким сущностям и полноценного центра уведомлений.
- Интерфейс тёмный; дополнительная светлая тема требует проверки каждого компонента.
- IP определяется по фактическому соединению; местоположение браузера добровольное и не является доказательством физического присутствия. Сетевые ограничения блокируют известные локальному реестру VPN/прокси, не гарантируют обнаружение любого VPN.
- Промышленная эксплуатация, другие компьютеры, Windows 8/8.1 и длительные нагрузки не проверены.

## Точка восстановления

Изначально Git-репозитория не было. Создан локальный исходный коммит, тег `superapp-baseline` и ветка `feature/superapp-redesign`. Секреты `.env`, базы, фотографии в базе, дампы, зависимости и сборки исключены из Git. Глобальные настройки Git не изменялись. PostgreSQL сохранён в `backup-before-superapp.dump`, исходный том не менялся.

Для просмотра исходного кода используйте `git show superapp-baseline:frontend/src/main.tsx`. Для безопасного получения исходной версии в отдельной папке используйте `git worktree add ../AegisBorder_baseline superapp-baseline`; не заменяйте текущие файлы и не восстанавливайте дамп поверх действующей базы без отдельного решения. Дамп содержит приватные данные и остаётся только локально.

## Последовательность безопасных изменений

1. Лендинг `/` без обращений к приватным API; переходы к защищённой панели `/app` и комиссии `/app/commission`.
2. Единая навигация `/app/...`, сохранение прежних прямых ссылок, современная оболочка и тема.
3. Workspace: отдельная миграция, документы/версии/комментарии, ограниченные права, оптимистическая блокировка, проверка содержимого, аудит и редактор.
4. Улучшение расследований и визуализаций; остальные модули только после реализации и проверок.

После каждого этапа обновлять результаты проверок. Изменения дизайна не требуют удаления или переименования существующих таблиц и API.
