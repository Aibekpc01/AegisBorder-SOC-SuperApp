# Render: адрес AegisBorder и самостоятельный публичный сервис

В проекте подготовлен `render.yaml`: Docker Web Service `aegisborder` и отдельная PostgreSQL-база `aegisborder-db`, оба с явным планом Free. Адрес назначает Render; имя `aegisborder.onrender.com` не гарантируется, если уже занято. Главная открывается по корню адреса; `/app` используется для рабочей панели.

## Сначала исходники на GitHub

Подготовленная папка: `release/render-source`. Архив: `release/AegisBorder-Render-source.zip`. Они содержат исходники и настройки сборки; рабочие `.env`, `.env.public-demo`, базы, дампы, `.git`, Docker-образы и `node_modules` исключены.

Удобный способ для первого раза — GitHub Desktop:

1. Войдите в GitHub Desktop через свою учётную запись GitHub.
2. Выберите File → New repository, имя `render-source`, Local path — папка `release` текущего проекта. Убедитесь, что конечный Repository path — именно подготовленная папка `release/render-source`.
3. Создайте репозиторий, включите все подготовленные исходники в commit и нажмите Publish repository. Название на GitHub можно изменить на `aegisborder`; оставьте репозиторий Private.
4. Не публикуйте весь рабочий каталог проекта с базой или секретами. Перед отправкой проверьте список файлов в GitHub Desktop.

Также можно создать приватный репозиторий в браузере и загрузить исходники через Add file → Upload files. В корне должны быть `render.yaml`, `Dockerfile`, папки `app`, `frontend`, `migrations`, а не один ZIP. Если интерфейс ограничивает число файлов, используйте GitHub Desktop.

## Затем Render

1. В панели Render нажмите New → Blueprint.
2. Подключите GitHub и разрешите доступ к приватному репозиторию `aegisborder`.
3. Выберите репозиторий. Blueprint Path — `render.yaml` в корне.
4. Перед созданием проверьте, что Web Service и PostgreSQL имеют Free-план. Если Free недоступен в аккаунте, не выбирайте платный автоматически.
5. Deploy Blueprint. Render соберёт Docker-образ, создаст отдельную базу и случайные `ADMIN_PASSWORD` / `AUDIT_KEY`. Локальная база не переносится.
6. После состояния Live откройте URL сервиса без `/app`. Для посетителя — кнопка «Попробовать без регистрации». Пароль администратора можно посмотреть в Environment своего сервиса; не отправляйте его в чат или GitHub.

Приложение читает `RENDER_EXTERNAL_URL`, поэтому HTTPS-origin и Secure-cookie настраиваются автоматически. Строка PostgreSQL приводится к установленному драйверу psycopg2. Порт берётся из `PORT`. Миграции запускаются перед сервером; проверка здоровья — `/api/v1/health`.

Публичные посетители имеют роль demo, личные события и материалы. Ключи корпоративных интеграций им недоступны. IP за Render-прокси может быть адресом инфраструктуры, пока администратор не настроит доверенные прокси; все заголовки без такой настройки не считаются достоверными.

## Ограничения Free

Бесплатный Web Service засыпает после отсутствия запросов и может открываться с задержкой. Бесплатная PostgreSQL-база истекает через 30 дней. Для постоянной работы заранее предусмотрите резервную копию и перенос базы. Конфигурация подготовлена и локальные проверки прошли; запуск в вашем Render ещё не выполнен.

Официальные источники: [Blueprint](https://render.com/docs/blueprint-spec), [автоматические переменные Render](https://render.com/docs/environment-variables), [Free](https://render.com/docs/free).
