# Техническая спецификация

Цель — демонстрационная система анализа синтетических событий для самостоятельной проверки комиссией. Система не подключается к служебной инфраструктуре и не выполняет защитные действия на реальных компьютерах.

Реализованы 14 разделов, 15 генераторов учебных ситуаций, детерминированная корреляция, жизненный цикл инцидента, комментарии, расследования, PDF, управление учётными записями, HMAC-аудит и отдельный анализ аномалий.

Жизненный цикл: Новый → На проверке → Подтверждён → Устранён → Закрыт. Из первых двух этапов доступно Ложное срабатывание. Пропуск этапов запрещён API.

Обязательные поля события: внешний уникальный идентификатор, время с часовым поясом, устройство, учётная запись, источник, тип, описание. Числовые и логические признаки проверяются. Повторный идентификатор в собственном контуре возвращает существующее событие; в чужом — конфликт.

Правила коррелируют по владельцу, демонстрационному сеансу, устройству, учётной записи, источнику и времени. Окно включительно: [t − окно, t]. Повторное предупреждение одного правила подавляется в пределах 300 секунд. Уже связанные доказательства при повторном анализе используют существующий инцидент.

Пороги по умолчанию:

| Ситуация | Проверяемый признак | Окно | Риск |
|---|---|---:|---:|
| Ошибки входа | ≥5 login_failed | 60 с | 65 |
| Необычное время | час до 08 или с 20, UTC+5 | 60 с | 55 |
| Закрытые файлы | file_denied и restricted=true | 60 с | 70 |
| USB | usb_connected и approved=false | 60 с | 60 |
| Сервер | heartbeat_lost, сервер, разрыв ≥120 с | 180 с | 85 |
| Активность ПК | CPU ≥90, процессов ≥50 | 60 с | 65 |
| Критические файлы | file_changed, critical=true | 60 с | 85 |
| Копирование | ≥3 операции, сумма ≥500 файлов | 60 с | 75 |
| Журналы | log_deleted | 60 с | 90 |
| Сеть | ≥3 network, approved=false | 60 с | 65 |
| Повышение прав | admin без согласования | 60 с | 90 |
| Нарушения | ≥3 policy_violation | 300 с | 70 |
| Поведение | unusual=true, объём ≥5 базовых | 60 с | 70 |
| Настройки | защита отключена без согласования | 60 с | 85 |
| Комплексный | ошибки → успешный вход → закрытый файл | 60 с | 95 |

После ошибок успешный вход добавляет 15 к риску; последующий закрытый ресурс — ещё 15. Верхний предел 100. Это оценка по доказательствам, не вероятность атаки. Комплексный сценарий использует и усиливает правило входа; отдельного дублирующего правила нет.

Границы отображения: 0–39 низкий, 40–64 средний, 65–84 высокий, 85–100 критический. Порог, окно и базовый риск изменяются администратором с записью аудита. Порог 1–1000; окно 10–3600 секунд; риск 1–100.

Ограничения 0.3: нет импорта реальной телеметрии, удалённого управления, гарантии точности ML, защищённого промышленного размещения и проверки Windows 8/8.1. Дедлайн целевого релиза — 20 ноября 2026 года; текущая версия требует дальнейшего приёмочного аудита.
