# Проверки

```powershell
.venv/Scripts/python.exe -m pytest -q
.venv/Scripts/python.exe -m ruff check app/command app/main.py migrations tests/test_command.py tests/conftest.py
cd frontend
npm.cmd run build
npm.cmd run lint
npm.cmd test
npm.cmd run e2e
npm.cmd audit
```

Pytest использует отдельную SQLite в памяти с включёнными внешними ключами. Покрыты 15 сценариев, порог и окно ошибок входа, повторный ID, роли, чужие сеансы, переходы статусов, комментарии, вывод, PDF, модель, отзыв JWT и Origin. Это функциональные проверки; формальной метрики покрытия пока нет.

Vitest проверяет границы риска, отображаемые переходы и объединение классов. Playwright запускает установленный Microsoft Edge на локальном адресе 8000 и проверяет UI комиссии до PDF и сброса созданного тестового сеанса, а также все разделы, поиск, фильтр и форму правил. Перед браузерными тестами через запущенный Docker-контейнер создаётся отдельная учётная запись со случайными реквизитами; после тестов она отключается. Действия записываются в аудит. Пароль пользователя и .env не меняются. Для запуска нужны Docker и доступ к браузеру. Основные данные не сбрасываются.

Результаты браузера и снимки сохраняются в frontend/test-results, PDF также находится там. Тесты меняют состояние тестового учебного сеанса и добавляют аудит. Сводка фактически выполненных проверок — в testing-results.md.

Дополнительно проверяются интерактивный полигон: поиск и категории, картинка-инструкция из шести нажимаемых SVG-блоков, фактические события выбранного запуска, раскрытие признаков USB, переход к расследованию и отсутствие горизонтального переполнения страницы на ширине 390 пикселей.

Проверка профилей загружает одноцветное учебное фото, меняет вымышленные поля, читает историю IP и передаёт заданные тестовым браузером координаты. Проверка сетевой политики временно добавляет зарезервированный учебный диапазон VPN и восстанавливает предыдущую конфигурацию. Физическая геолокация машины не считывается; реальные VPN и сторонние IP-сервисы не используются.

Дополнительная проверка старого прототипа: tests/check_project.py через Docker использует legacy_main, создаёт временную схему PostgreSQL и удаляет её после проверки. Новая версия проверяется отдельно.

Новая версия на PostgreSQL: `$OutputEncoding = [System.Text.UTF8Encoding]::new($false)`, затем `Get-Content -Raw -Encoding UTF8 tests/check_postgresql.py | docker compose exec -T app python -B -`. Проверяются 15 ситуаций и 24 конкурентные подачи одного события. Созданная этим тестом временная схема удаляется; основная база не меняется.
