# Документы и рабочее пространство

Откройте `/app/workspace` после входа. Выберите «Создать документ», название, шаблон и при необходимости инцидент. Доступны материалы расследования, учебная служебная записка и пустой документ.

## Работа оператора

1. Заполните текст. Панель редактора позволяет выделять текст полужирным и курсивом, добавлять заголовки, списки и таблицу 3×3. В таблице можно добавлять строки и удалять её.
2. Укажите ответственного и инцидент из доступных вам записей.
3. Через секунду после изменения начинается автосохранение. Дождитесь отметки «Сохранено · версия …». Кнопка «Сохранить сейчас» выполняет ту же серверную операцию.
4. Добавляйте заметки внизу документа. Они сохраняются отдельными записями.
5. Отправьте материал «На проверке». Аналитик или администратор с правом редактирования может утвердить его. Для дальнейших правок сначала отдельно верните утверждённый документ в черновик.
6. Откройте «История версий» и выберите запись для просмотра. Это не заменяет действующий текст и не восстанавливает старую версию автоматически.
7. Вернитесь к списку; поиск проверяет название и текст. Обновление страницы сохраняет материалы в базе, хотя редактор после обновления возвращается к списку.

Не закрывайте окно до подтверждения сохранения. Переход по ссылке при несохранённых изменениях блокируется; браузер предупреждает о закрытии вкладки. При конфликте версий текст не перезаписывается автоматически: скачайте JSON-копию и загрузите актуальную версию. Автоматическое объединение текста нескольких операторов не реализовано.

## Доступ и целостность

- Наблюдатель читает разрешённые общие документы и версии; создавать, редактировать и комментировать не может.
- Аналитик редактирует свои и назначенные ему документы. Администратор редактирует общие документы.
- Демонстрационный пользователь видит только собственные материалы. Связь с личным учебным инцидентом делает материал изолированным; снятие связи не превращает его в общий.
- При сбросе своего учебного сеанса документ сохраняется, связь с удалённым учебным инцидентом снимается, создаётся версия и запись аудита. Это отдельный явно журналируемый системный переход, в том числе для утверждённого материала.
- Сервер проверяет версию перед обновлением и использует условное обновление SQL. Устаревшая копия получает 409.
- Содержимое хранится как JSON-дерево с белым списком узлов и форматирования. Изображения, ссылки, HTML-вставки, произвольные атрибуты и внешние ресурсы не разрешены. Текст вроде `<script>` остаётся текстом, а не HTML. Ограничения: 200 КБ, 3000 узлов, глубина 16, заголовки 1–3.
- Каждая версия и текущий документ проверяются по HMAC; изменение записей вне предусмотренного API обнаруживается. Секрет AUDIT_KEY нужно сохранять при переносе существующей базы.

## API и таблицы

`GET /api/v1/workspace/templates` — шаблоны.

`GET/POST /api/v1/workspace/documents` — поиск и создание.

`GET/PUT /api/v1/workspace/documents/{id}` — чтение и сохранение; PUT включает текущую revision, title, content, incident_id, assignee_id, status.

`GET /api/v1/workspace/documents/{id}/versions` — последние 100 версий с содержимым для просмотра.

`POST /api/v1/workspace/documents/{id}/comments` — заметка.

Миграция 004 добавляет `cc_workspace_documents`, `cc_document_versions`, `cc_document_comments`, внешние ключи, индексы и ограничения. Существующие таблицы не удаляются. Автосохранение одинаково использует API в PostgreSQL и локальном SQLite; SQLite — облегчённый режим.

Дополнительные DOCX/PDF-экспорты документов, восстановление версии, совместное редактирование и задачи согласования ещё не реализованы. PDF инцидентов продолжает работать отдельно в прежнем разделе отчётов.

Редактор основан на [официальной интеграции Tiptap для React](https://tiptap.dev/docs/editor/getting-started/install/react) и [расширении таблиц](https://tiptap.dev/docs/editor/extensions/nodes/table). Во время работы браузер не обращается к сервису Tiptap.
