# Aegis DLP в Supperapp

Актуальная версия без Python, со службой, треем и обязательным доступом:
[Aegis DLP 2.0](aegis-dlp-native.md). Ниже сохранено описание предыдущего пилота.

Раздел `/app/dlp` доступен разработчику и ролям с рангом выше разработчика:
аналитик, руководитель команды, заместитель CTO, администратор, CTO, создатель.
Аудитор, наблюдатель и демонстрационные роли доступа не имеют. Проверка выполняется
на сервере и в навигации. Новое разрешение `permissions.dlp` возвращает `/auth/me`.

## Подключение

1. Пользователь входит на сайт с Windows-ПК; присутствие сохраняется в «Устройствах».
2. В Aegis DLP выбирает собственный Windows-ПК, задаёт имя и скачивает ZIP.
3. Распаковывает ZIP на целевом компьютере и явно запускает `setup.ps1`.
4. Установщик требует заранее установленный Python, создаёт виртуальное окружение,
   устанавливает зависимости (из сети или локальной папки wheels), запрашивает
   отдельный пароль Aegis DLP и регистрирует задачу при входе текущего пользователя.
5. При первом heartbeat ключ привязывается к экземпляру агента; в панели появляется
   имя компьютера и наблюдаемый сервером IP. Это не подтверждение физической личности
   устройства: пакет может быть перенесён до активации. Для аппаратной аттестации
   потребуется отдельный этап с сертификатами/TPM.

Браузер не устанавливает программы на компьютер самостоятельно. Пакет предназначен
для Windows 10/11, не для телефона. Скрипт пилота не подписан: запуск подчиняется
локальной политике PowerShell организации. Политика исполнения глобально не меняется.
Установщик не включает USB-блокировку. Автозапуск — задача пользователя, не служба,
после выхода из Windows агент не работает. Автономная локальная USB-политика Windows
при этом остаётся применённой. Удаление задачи производится администратором Windows
в планировщике, USB-политику восстанавливает отдельная парольная команда usb-restore.

## Данные и мониторинг

Агент отправляет heartbeat каждые 30 секунд после завершения сбора, UI опрашивает
сервер каждые 5 секунд. Через 100 секунд без heartbeat отображается «Нет связи».
Это не утверждение о текущей исправности защиты на отключённом ПК. Состояния:
ожидает установки, на связи, нет связи, ключ отозван.

Показываются последние полученные антивирусные статусы, возраст баз, локальные флаги
чтения/записи съёмных дисков, CPU/RAM, размер недоставленной очереди, 60 последних
heartbeat и 50 последних событий. Значение «нет данных» не считается безопасным.
Ошибки чтения Defender отображаются отдельно. Чтение реального состояния Windows
проверено без изменения политик, запуска проверок или установки агента.

События с локального диска отправляются с подтверждением и дедупликацией в обычный
журнал событий Supperapp; правила корреляции работают как для других источников.
Источник и имя ПК задаются сервером, ID событий изолированы по ключу устройства.
Объём очереди ограничен 10 000 ожидающими событиями; сбор сообщает об исчерпании.

## Доступ и ключи

Каждый ZIP содержит собственный ключ активации (24 часа до первого подключения).
Сервер хранит SHA-256-хеш. Содержимое ZIP нельзя публиковать или пересылать посторонним.
После инициализации установленная копия ключа защищена Windows DPAPI CurrentUser.
Исходный скачанный ZIP остаётся чувствительным: его необходимо удалить или защитить.
Пакет не содержит пароль сайта. Локальные настройки защищены отдельным Argon2-паролем;
пять ошибок блокируют попытки на пять минут. Это не защита от администратора Windows.

Мониторинг доступен разрешённым техническим ролям, отзыв — владельцу ПК, руководителю
команды, заместителю CTO либо административной роли. При блокировке владельца или
снятии с него разрешённой роли телеметрия перестаёт приниматься. Отзыв ключа прекращает
синхронизацию, но не отменяет ограничения на ПК. Удалённых shell-команд нет.

Производственные требования следующего этапа: подписанный MSI, системная служба,
ACL на каталоги, шифрование SQLite, аппаратная привязка и испытания фактического
USB-запрета. Текущая интеграция — мониторинг пилота, не сертификат полноценной DLP.

## Публикация 15 октября 2026

Опубликовано: https://aegisborder.130.61.214.154.sslip.io/app/dlp .
Образ `aegisborder-dlp:20261015-r5`, ARM64, схема `010_dlp`.
Приложение, PostgreSQL и прокси работают с автоматическим перезапуском.

Проверки: полный backend-набор 145 тестов, затем два новых сценария ограничения
чужого подключения и отключения владельца в составе 15 целевых DLP-тестов;
27 frontend-тестов, Ruff, ESLint и production build. Четыре локальные браузерные
группы и две опубликованные проверяют доступ и размеры 1440/390. Пять групп на
восстановленной отдельной PostgreSQL проверяют миграцию, ZIP, передачу очереди,
привязку экземпляра, дедупликацию, роли, отзыв ключа и целостность аудита.
DPAPI и чтение настоящего состояния Windows проверены без установки агента.
Установщик и фактическая USB-блокировка на компьютере не запускались.

При публикации был краткий перерыв: строгая сверка учётных записей обнаружила
параллельное изменение роли/пароля через пользовательскую панель и вызвала откат.
Прежний образ не распознал новую миграцию. Восстановлен проверенный новый образ,
сохранены все 16 учётных записей, включая параллельное изменение. После восстановления
проверены вход, раздел DLP, состояние контейнеров и новая резервная копия.

При откате на старый образ нужно предоставить ему файл миграции `010_dlp.py`
через read-only bind mount: существующая добавленная таблица совместима со старым
приложением, но Alembic должен знать текущую ревизию. Не сбрасывать номер ревизии
и не восстанавливать всю старую базу поверх новых пользовательских изменений.
