Аудит готовности AegisBorder к презентации

Вывод: проект готов к управляемой учебной презентации с подготовленным сценарием. Работает основной путь от события до расследования, PDF и документа. Для открытого показа предпочтительна подготовленная сборка с исправлениями этого аудита. Промышленная эксплуатация со служебными данными требует отдельной приёмки.

Проверка начата 17 октября 2026 года. Опубликованная версия — emblems-20261017-r15, адрес рабочего сайта. Исправления сохранены в текущем проекте и собраны в отдельный ARM64-образ для временного проверочного контура. Рабочий сайт на этот образ не переключался.

Для полного основного показа можно выбрать «Попробовать без регистрации»: роль demo позволяет сохранить своё расследование, PDF и документ. Этот путь проверен в браузере. Роль demo_viewer предназначена для просмотра и ограниченных тренировочных действий; редактирование расследования и документов ей запрещено. Административный показ требует подготовленного входа и выполнения назначенных требований DLP.

Исправления этого аудита

Приоритет Проблема и влияние Исправление и проверка
Средний CTO или администратор мог менять ФИО, подразделение и должность создателя через /presence/employees/{id}, хотя основной профиль запрещал это. Изменение пароля или роли этим обходом не подтверждено. В presence.py добавлена общая проверка иерархии. Два новых теста воспроизвели HTTP 200 до исправления и проверили 403 после него. Разрешённые действия со своим и нижестоящим профилем сохранены.
Средний За доверенным прокси все посетители попадали в одну корзину ограничений входа и записывающих запросов. Один посетитель мог исчерпать общий лимит. В api.py применяется существующее определение проверенного клиентского адреса. Три теста проверяют разделение лимитов, сохранение ограничения и отказ доверять поддельному X-Forwarded-For. Проверка повторена в ARM64-контейнере.
Средний Светлая тема содержала бледный текст и тёмные карточки с тёмными надписями. Участники чата не могли попасть клавиатурой в прокручиваемый список. Интерактивный граф был объявлен изображением. Общие цвета и поверхности светлой темы приведены к согласованным значениям; список получил фокус и подпись; граф — роль группы; текстовая ссылка получила подчёркивание.
Низкий Во время проверки DLP отображались строки из вопросительных знаков; пустая пагинация событий показывала 1–0. Восстановлен русский текст; для пустого списка отображается 0–0.
Низкий Даты CERT-EU с суффиксами CET/CEST отображались как Invalid Date. Добавлено преобразование этих часовых поясов и безопасное сообщение для непонятной даты. Пять новых клиентских тестов.
Эксплуатационный Скрипт резервирования жёстко использовал проект aegis-oracle и .env.oracle, тогда как текущий сервер использует другое имя Compose-проекта и два файла конфигурации. Добавлены параметры --project, --env-file, повторяемый --compose-file. Три теста проверяют правильный выбор цели и отсутствие окончательного файла после сбоя или пустого дампа.
Низкий ESLint выдавал 31 ошибку окружения новых браузерных скриптов; Ruff — 3 замечания в импортах. Настроены глобальные имена нужных Playwright-скриптов, упорядочены импорты. Финальные проверки проходят.

Изменения исходников не означают обновление опубликованного сайта. Публичная версия остаётся r15; подготовленный образ предназначен для последующего контролируемого выпуска с резервной копией и откатом.

Что остаётся перед открытым показом и эксплуатацией

  1. Публикация исправлений и репетиция на нужном ПК. Основной учебный маршрут уже работает; административный браузерный сеанс может потребовать подтверждения DLP. Проверять нужно тот же браузер и устройство, которые будут подключены к проектору.
  2. Автоматические и внешние резервные копии. В просмотренных заданиях cron/systemd не найдено резервирования приложения. Копия на той же VM не защищает от потери VM. Нужны защищённая копия вне сервера, сохранение необходимых ключей конфигурации и регулярная репетиция восстановления. Проверка этого аудита использовала действующее окружение приложения.
  3. Приватность каталога сотрудников. Публичный гость может читать имена, роли, подразделения и присутствие сотрудников через каталог. IP других пользователей ему не выдаётся. Перед внешним показом использовать вымышленные карточки либо ограничить видимость каталога для гостей.
  4. Ограничение регистрации гостей за общим NAT. Сохраняется намеренный лимит десяти новых тренировок за час с одного внешнего IP. Для аудитории с общим университетским адресом лучше заранее открытые сеансы или отдельный механизм приглашений. Исправление прокси не отменяет этот лимит.
  5. Защитные заголовки и контейнер. HTTPS перенаправление 308, nosniff, DENY и same-origin присутствуют. CSP и HSTS в проверенном ответе отсутствуют. CSP вводить с проверкой загрузок и WebSocket; затем включать рабочую политику. Контейнер приложения сейчас запускается с пользователем по умолчанию root; перед эксплуатацией нужны отдельный непривилегированный пользователь и лимиты ресурсов.
  6. Скорость первого открытия. Эмблема занимает около 1,4 МБ, иллюстрации — около 1,8 и 2,1 МБ. Нужны варианты по размеру, современные форматы и политика кеширования хешированных ресурсов. Мобильная главная длинная; основной показ следует вести по короткому маршруту, а не прокручивать весь каталог.
  7. API и обработка адресов. Документация API открыта публично; это само по себе не обход доступа. Служебные и неизвестные URL могут получать оболочку приложения с HTTP 200. Для закрытого выпуска нужны осознанная политика документации, корректные служебные файлы и 404 с сохранением прежних допустимых ссылок.
  8. Windows-пилот. Для массовой установки нужны цифровая подпись издателя, чистая установка, обновление, удаление, восстановление USB-политики, проверка разных браузеров и конфликтов с доменной политикой. Самоотчёт агента не является аппаратной аттестацией.
  9. Архитектура и длительные испытания. api.py и command-center.tsx остаются крупными, frontend широко использует Row/any. Нужны постепенные DTO и разделение модулей, CI, более длительные испытания и независимый обзор безопасности.
  10. Фиксация проверенной версии. Рабочая папка содержит изменённые и новые, ещё не отслеживаемые Git файлы, включая серверные модули и миграции. Текущий HEAD не является снимком проверенного проекта. Подготовлен отдельный архив исходников; перед следующим выпуском нужно зафиксировать выбранные код, тесты, миграции и документацию без секретов. Нативный EXE собирается отдельно в Windows; исходный архив не заменяет пакет поставки агента.

Приоритетные идеи развития

Очерёдность Идея Польза и критерий готовности
Сначала Проверка готовности к показу в одном экране Проверяет API, роль, DLP текущего сеанса, наличие нативной сборки и возможность получить отчёт. При отказе показывает конкретную причину и следующий шаг.
Сначала Короткий маршрут для комиссии Использует существующий режим демонстрации: одна ситуация, шесть этапов, конечный PDF. Скрывает второстепенные блоки, сохраняет возврат к нужному шагу и крупный текст для проектора.
Сначала Пакет показа без зависимости от сети PDF, снимки, схема архитектуры, краткий сценарий и запись заранее проведённой демонстрации. Он явно отделён от работающего приложения.
Сначала Сведения о текущем релизе Показывает версию сборки, время выпуска и фактический статус функций. Комиссия видит разницу между работающей функцией, учебным примером и планом.
Затем Сравнение нарушения и нормального поведения Один и тот же сценарий запускается с изменённым признаком. Интерфейс объясняет, почему правило сработало или не сработало. Это использует существующие отрицательные проверки и делает результат убедительнее.
Затем Улучшенный отчёт расследования Титул, ответственный, явный часовой пояс, хронология, доказательства и ссылки на версию. Проверка результата человеком остаётся обязательным этапом.
Затем Приглашения для учебной группы Ограниченные приглашения и изолированные рабочие области вместо массового создания гостей с одного IP. Нужны срок действия, ограничения роли и уборка истёкших тренировок.
Затем Один реальный интеграционный пилот Выбрать разрешённый источник и проверить полный путь: событие, доставка, повтор, недоступность, восстановление и отображение. Показать измеренный результат одного адаптера вместо списка неподтверждённых интеграций.
После пилота Проверяемый AI-помощник Черновик с ID использованных доказательств и явными неопределённостями. Подключение внешней LLM потребует отдельного API-доступа, бюджета и правил обработки данных; Edu само по себе не подключает модель к приложению.
После пилота Измеримая оценка обнаружения Размеченный независимый набор, разделение обучающих и проверочных данных, ложные срабатывания и пропуски. Только после этого публиковать показатели качества модели.

На ближайший этап полезнее повысить надёжность и ясность существующего пути, чем увеличивать количество разделов.

Как повторить основные проверки

.venv/Scripts/python.exe -m pytest -q
.venv/Scripts/python.exe -m ruff check app migrations scripts tests
cd frontend
npm.cmd test
npm.cmd run lint
npm.cmd run build

После установки обновлённого скрипта на существующий сервер его фактической конфигурации соответствует команда:

python3 scripts/backup_oracle.py --project aegisborder_soc_v02 --env-file .env --compose-file compose.yaml --compose-file compose.oracle.yaml

Скрипт создаёт дамп; он не заменяет отдельное защищённое хранение необходимых настроек и не выполняет восстановление поверх рабочей базы.
