# AEGIS ULTRA — реализация и проверка

Дата: 15 октября 2026. Ветка: `feat/aegis-ultra`.

Новый интерфейс реализован в существующем React-приложении. Маршруты, расследования, документы, обучение, отчёты и Docker Compose сохранены. Первоначально версия проверялась локально. После отдельного подтверждения владельца «добавь его на мой сервер оракл» версия опубликована на Oracle 15 октября 2026 года; результаты публикации приведены ниже.

## Публикация на Oracle

Адрес: https://aegisborder.130.61.214.154.sslip.io/.

- Активный образ: `aegisborder-ultra:20261015-r1`, ARM64, image ID начинается с `c80cbed8a526`.
- Исходники релиза: `/home/ubuntu/aegisborder-releases/ultra-20261015-r1`.
- Защищённая резервная копия: `/home/ubuntu/aegisborder-backups/ultra-20261015-r1`. Содержит проверенный дамп PostgreSQL, конфигурацию, `.env`, прежние исходники и ID образа.
- Образ возврата: `aegisborder-ultra:rollback-20261015-r1`.
- Обновлён только контейнер приложения. PostgreSQL, его том, Caddy, сертификаты и домен сохранены. В активной `compose.oracle.yaml` закреплён новый образ; актуальные исходники приложения также перенесены в рабочий каталог.
- Четыре существовавшие перед публикацией учётные записи сохранили логины, роли, активность и хеши паролей; это проверено сравнением отпечатков.
- HTTPS `/api/v1/health`, главная и вход администратора возвращают 200. Авторизованный сеанс администратора работает, проверочный сеанс завершён. Цепочка аудита валидна.
- Браузер проверил опубликованные главную, экран входа, панель, двойник и ИИ-центр. Публичный вход возвращает `demo_viewer`; изменение настроек отклоняется с 403. Ошибок JavaScript нет.
- Локальные материалы публикации: `release/aegis-ultra/production-build.log`, `production/checks.json`, `production/{landing,login,dashboard}.png`.

На Oracle отсутствует Buildx, поэтому необязательный `$BUILDPLATFORM` удалён из Dockerfile для совместимости с установленным builder. На сервер не устанавливались дополнительные компоненты Docker. Перед переключением приложение продолжало обслуживать посетителей прежним образом; во время пересоздания контейнера возможна короткая пауза.

Для возврата старой версии восстановить `compose.oracle.yaml` из указанной резервной копии, назначить тег `aegisborder_soc_v02-app` сохранённому образу возврата и выполнить из рабочего каталога `sudo docker compose -p aegisborder_soc_v02 -f compose.yaml -f compose.oracle.yaml up -d --no-build --no-deps --wait app`. Возврат образа не требует удаления или восстановления базы. При необходимости полного отката исходников использовать защищённый `previous-source.tar.gz`; не удалять том PostgreSQL.

## Данные и права

Схема использует `/superapp/twin`: устройства, упомянутые учётные записи и пары из сохранённых событий. Размещение условное и явно подписано. Оно не означает физические соединения или географические координаты. Отображается до 36 узлов; исходная выборка ограничена 2000 событиями. Детали рисков и инцидентов поступают из API. Число источников — число значений в выборке, а не утверждение об исправности внешних подключений.

SVG и CSS создают объёмную композицию без новой 3D-зависимости и без WebGL. Поэтому интерфейс остаётся доступным на компьютерах без GPU/WebGL; отдельный запасной canvas не нужен. ИИ-ядро отражает состояние реального запроса. Оно не изображает работу подключённой языковой модели: существующий помощник по-прежнему составляет объяснимый черновик из фактов.

`demo_viewer` сохраняет только собственные синтетические сценарии, результаты анализа и разрешённые отчёты. Остальные изменения запрещены в общей серверной зависимости `current`, а не только скрыты в интерфейсе. Новый публичный вход — `/api/v1/auth/demo-viewer`; существующий режим `demo` сохранён для совместимости. Постоянные настройки, пользователи, интеграции, задачи и сброс данных недоступны для изменения viewer. Чужие учебные записи и общая инфраструктура не попадают в его выборки.

Административный архив и корзина добавлены для задач; состояние сохраняется в существующей таблице настроек без изменения схемы. Массовое действие проверяет все версии до применения. Удаление в корзину обратимо. Для задачи со ссылкой на инцидент оно запрещено: доступно архивирование. События, расследования и журналы аудита не получили опасных действий удаления или переписывания. В карточках пользователей добавлены контекстные действия и подтверждение отключения/восстановления доступа.

Порядок и видимость виджетов сохраняются отдельно для пользователя в браузере. Перемещение выполняется командами «выше/ниже» в меню: это доступно и с клавиатуры. Кнопка восстановления возвращает стандартную панель.

## Результаты проверок

- Backend: **103 теста прошли**; журнал — `release/aegis-ultra/backend-tests.log`.
- Frontend: **13 тестов в 6 файлах прошли**; журнал — `release/aegis-ultra/frontend-tests.log`.
- ESLint и Ruff: ошибок нет.
- TypeScript и production-сборка Vite: успешно; журнал — `release/aegis-ultra/frontend-build.log`.
- Браузер: **11 сквозных проверок прошли**, включая все 27 маршрутов, виджеты, поиск, узлы, расследование, анализ, архив задач, презентацию, размеры экранов и viewer. Ошибок JavaScript нет. Протокол — `release/aegis-ultra/final/checks.json`.
- Вступление: проверены фокус, Tab, пропуск, повтор, Escape, одноразовый показ и `prefers-reduced-motion`.
- Docker ARM64: отдельный образ `aegisborder-ultra:review` успешно собран и запущен; архитектура процесса — `aarch64`. **11 проверок запуска прошли**: здоровье, страницы, вход, cookie-сеанс, выход, viewer, запрет изменения настроек и личный синтетический сценарий. Журналы — `release/aegis-ultra/docker-arm64-build.log`, `docker-arm64-runtime.log`, `docker-arm64-runtime.json`. Проверочный контейнер использовал временную SQLite-базу и затем был остановлен. Production PostgreSQL в этой проверке не использовался; серверные проверки прав дополнительно выполнены в общем наборе тестов.

Предупреждение тестовой среды о переходе Starlette с `httpx` на `httpx2` сохранено в журнале; тесты проходят. Docker BuildKit предупреждает, что не смог прикрепить сведения Git-коммита из-за владельца рабочего дерева; это не ошибка сборки. Предсуществовавшие правки пользователя не объединялись в общий коммит.

Статические файлы frontend не зависят от архитектуры процессора; runtime проверен на ARM64. Для совместимости со старым Docker builder сервера сохранён исходный формат `FROM` без обязательной зависимости от Buildx и `$BUILDPLATFORM`.

## Локальная проверка и откат

Из корня проекта:

```powershell
.venv/Scripts/python.exe scripts/preview_ultra.py
```

В другом терминале, из `frontend`:

```powershell
$env:AEGIS_API_TARGET = 'http://127.0.0.1:8011'
npm.cmd run dev -- --port 5174
```

Для браузерной проверки:

```powershell
node scripts/ultra-verify.mjs
node scripts/ultra-intro.mjs
```

Сервер предварительного просмотра использует отдельную SQLite-базу в `release/aegis-ultra/preview.sqlite`. Случайные локальные данные входа находятся в исключённом из Git/Docker `.env.ultra-preview`, ключ аудита — в исключённой папке `release/`. Для просмотра пароль не нужен: используйте кнопку демонстрационного просмотра. Не переносите эти файлы на production.

До изменения сохранены `release/aegis-ultra/before/src`, `before/command`, `before/package.json` и `before/tracked-changes.patch`. Они содержат исходное состояние с уже имевшимися правками пользователя. Для локального отката сначала сохраните новые изменения отдельно, затем восстановите затронутые исходники из этих копий и соберите frontend. Простое переключение ветки не отменяет незакоммиченные изменения. Не используйте `git reset --hard` для этого рабочего дерева.

Перед разрешённой публикацией: сделать дамп production-БД и сохранить `.env` на сервере, сохранить текущий образ и версию исходников, собрать новый образ, переключить только приложение, проверить здоровье, HTTPS, вход и права. Caddy, домен и том PostgreSQL сохраняются. Для возврата использовать прежний образ и прежние исходники; production-базу не удалять и не выполнять `down -v`.

Точность модели на реальной инфраструктуре, частота кадров на физическом офисном ПК и производительность на настоящем 4K-мониторе не измерялись. Браузерные проверки размеров и ARM64-эмуляция не заменяют такие измерения.
