# AegisBorder SOC — рабочий прототип v0.2

**Назначение:** изолированная учебная система кибербезопасности. Никаких реальных атак, сканирований или сетевых блокировок.

## Установка на Windows 10

1. Установите Docker Desktop с WSL2 и включённой виртуализацией (только на личном или согласованном компьютере).
2. Распакуйте архив, например в `C:\AegisBorder_SOC_v0.2`.
3. Откройте PowerShell в папке проекта.
4. Создайте файл настроек: `Copy-Item .env.example .env`.
5. Откройте `.env` в Блокноте и замените все три значения. Пароли должны быть уникальными, `ADMIN_PASSWORD` не короче 12 символов, `AUDIT_KEY` не короче 32. Не используйте в пароле базы символы `@`, `:`, `#`, `/`, `%` (упрощённая строка подключения). Не передавайте `.env` третьим лицам.
6. Запустите Docker Desktop, дождитесь готовности.
7. Выполните `docker compose up --build -d` (либо двойной щелчок по `Запустить.bat`). Первый запуск скачает Docker-образы и Python-зависимости, поэтому нужен интернет.
8. Проверьте `docker compose ps`. Приложение должно иметь статус `Up`.
9. Откройте **http://127.0.0.1:8000**. Вход: `admin` и пароль `ADMIN_PASSWORD` из `.env`.
10. Если что-то не работает, выполните `docker compose logs --tail=100 app`.

## Что уже работает

Интерфейс реализован на HTML, CSS и обычном JavaScript; React и Node.js для запуска не требуются.
Ключ `AUDIT_KEY` проверяется при старте: требуется не менее 32 символов.
`ADMIN_PASSWORD` применяется только при первом создании администратора. Изменение `.env` не меняет пароль существующей учётной записи.
Скрипт `Запустить.bat` ожидает готовности приложения и базы перед открытием браузера.

## Проверка исправлений

Проверка сценария, статусов, очистки и параллельного аудита выполняется в отдельной временной схеме PostgreSQL, которая удаляется после теста. Основные данные не меняются. Выполнять после запуска контейнеров:

```powershell
$OutputEncoding = [System.Text.UTF8Encoding]::new($false)
Get-Content -Raw -Encoding UTF8 tests/check_project.py | docker compose exec -T app python -B -
```

При записи аудита в PostgreSQL используется транзакционная блокировка для сохранения последовательности цепочки. Режим SQLite предназначен для разработки и не обеспечивает эту гарантию при параллельной записи.

## Функции интерфейса

- Русскоязычный адаптивный интерфейс с авторизацией.
- PostgreSQL с постоянным томом данных.
- Главная панель, мониторинг событий, управление статусами инцидентов.
- 10 синтетических сценариев, запускаемых пользователем.
- Журнал аудита с HMAC-цепочкой и проверкой целостности.
- Простая инструкция нового сотрудника.
- API: http://127.0.0.1:8000/docs (для методов данных нужен токен).

## Что пока НЕ реализовано

Это **v0.2**, не завершённая платформа из 25 модулей. Нет реального EDR/SIEM-сбора, машинного обучения, WebSocket, цифрового двойника, ролевого администрирования, экспорта отчётов, интерактивного тура и промышленного реагирования. Оценка риска и объяснение пока заданы учебными сценариями. PostgreSQL-схема создаётся автоматически; миграции Alembic будут добавлены позднее.

## Важные ограничения

- Система предназначена только для демонстрационных данных и локального компьютера.
- Docker-приложение доступно только через 127.0.0.1; не открывайте порт в сеть.
- Уровень защиты v0.2 недостаточен для эксплуатации с реальными служебными сведениями.
- Ключ аудита хранится в `.env`: для промышленной проверки нужны внешний якорь доверия и управление ключами.
- В этой версии создаётся один администратор; роли наблюдателя и аналитика предусмотрены в коде, но интерфейса управления ими нет.
- `docker compose down` останавливает сервисы, но сохраняет данные. `docker compose down -v` **удалит базу**.

## Быстрый тест

1. Откройте «Учебный полигон».
2. Запустите «Подбор пароля».
3. Перейдите в «Главную панель»: появятся 6 событий и 1 инцидент.
4. Откройте «Центр инцидентов» и поменяйте статус.
5. Откройте «Журнал аудита» и проверьте целостность.
6. Остановите контейнеры, запустите повторно: данные должны сохраниться.

## Полезные команды

- Запуск: `docker compose up --build -d`
- Остановка: `docker compose down`
- Логи: `docker compose logs -f app`
- Проверка: `curl.exe http://127.0.0.1:8000/api/v1/health`

## Резервная копия

`docker compose exec -T db pg_dump -U aegis aegisborder > backup.sql`

Восстановление требует отдельной процедуры и тестирования на копии базы.
