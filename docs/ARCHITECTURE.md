# Архитектура Command Center 0.3

Этап SuperApp: `frontend/src/main.tsx` — лёгкая точка входа с лендингом `/` и защищённым приложением `/app`. `command-center.tsx` сохраняет прежнюю логику; Workspace загружается отдельным модулем. Старые прямые ссылки остаются рабочими. Глобальный поиск использует прежние защищённые API.

Серверный модуль `workspace` хранит проверенный JSON редактора, версии с HMAC и комментарии. Условное SQL-обновление по ревизии предотвращает перезапись устаревшей копией. Миграция 004 только добавляет таблицы. См. `docs/workspace.md` и `docs/SUPERAPP_REPORT.md`.

React + TypeScript + Vite формируют интерфейс. Tailwind CSS, компоненты по паттернам shadcn/ui (Radix), Lucide и Recharts обеспечивают оформление. React Router управляет разделами, TanStack Query — данными API. Статическая сборка обслуживается FastAPI по тому же адресу, поэтому внешние CDN не нужны.

Модули сервера: `db` — подключение, `models` — сущности, `schemas` — входные данные, `security` — Argon2/JWT/аудит, `scenarios` — генерация событий, `detection` — корреляция, `analytics` — Isolation Forest, `reports` — PDF, `api` — маршруты. Дальнейшая декомпозиция большого файла маршрутов предусмотрена до релиза.

Поток: учебная ситуация → нормализация → сохранение события → проверка правил → предупреждение и связанные события → расследование → сохранённый снимок отчёта → PDF. Генератор не создаёт инциденты напрямую.

В PostgreSQL обработка событий и добавление аудита сериализуются транзакционными advisory-блокировками. WebSocket раз в две секунды передаёт ревизию событий и число инцидентов; браузер запрашивает обновлённые данные. Это уведомления о сохранённых данных, а не имитация телеметрии.

Прототип v0.2 сохранён в `app/legacy_main.py`, исходный интерфейс — в `app/static/index.html`. Его таблицы остаются в базе. Новая версия использует префикс `cc_`, исключая перезапись прежних данных.

Развёртывание в закрытой сети: сервер PostgreSQL и FastAPI, предварительно собранный frontend, внутренний TLS-прокси, ограничение доступа. Текущая Compose-конфигурация слушает только 127.0.0.1. Сборка требует интернета; исполнение после сборки не требует внешних API.
