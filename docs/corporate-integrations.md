# Корпоративные интеграции

В `/app/integrations` есть защищённые приёмники постоянного потока событий и отдельный импорт JSON/CSV. Администратор выбирает продукт, создаёт приёмник, получает адрес и ключ. Ключ показывается при создании или замене; в базе хранится его SHA-256, в списках и аудите ключа нет. Отключение приёмника и замена ключа прекращают доступ старого отправителя.

## Что значит подключение

«Ожидает настройки отправителя» — приёмник создан. «Ключ проверен» — внешний запрос успешно проверил API. «События поступают» — принят хотя бы один пакет; рядом показано время последнего поступления. Это не постоянный мониторинг доступности стороннего сервера. После отключения отображается «Отключён».

Передача: POST JSON на адрес приёмника, заголовок `Authorization: Bearer <ключ>`. Для корпоративной среды используйте HTTPS и сетевую политику. Максимум 200 событий и 200 КБ на запрос. Уникальные ID получают пространство имён приёмника; повторы не создают события. Весь пакет проверяется до записи; затем работает штатный Detection Engine. Не каждый тип события автоматически создаёт инцидент: настройте подходящее правило.

## Адаптеры

| Источник | Поддерживаемый контракт |
|---|---|
| Kaspersky | Агент преобразует экспорт в `id, timestamp, host, user, event, detail, features` |
| DLP | Агент преобразует экспорт в `event_id, timestamp, workstation, user, action, detail, features` |
| Microsoft Entra | `id, activityDateTime, initiatedBy, activityDisplayName`; используется источник Microsoft 365 |
| Другая система / SIEM | Штатный EventInput: `external_id, time, device, account, source, type, detail, features` |

Kaspersky и DLP здесь — контракты входящего обмена, а не заявления о совместимости со всеми версиями продуктов. Экспорт и преобразование настраивает администратор конкретного продукта. Встроенный DLP-анализ файлов и удалённая блокировка компьютера не реализованы. Универсальный API позволяет написать адаптер корпоративной системы без изменения основного процесса Aegis.

Для отправки подготовленного JSON есть `scripts/forward_events.py --endpoint <адрес> --file <экспорт.json>`. Ключ задаётся локально в `AEGIS_CONNECTOR_TOKEN`. `--check` проверяет API без создания событий. Агент не следует перенаправлениям, чтобы ключ не ушёл другому серверу.

## Автоматическое чтение Microsoft Entra

`scripts/pull_m365_audit.py --endpoint <адрес приёмника m365> --state <файл контрольной точки>` выполняет один цикл чтения и передачи. В окружении агента нужны `M365_TENANT_ID`, `M365_CLIENT_ID`, `M365_CLIENT_SECRET`, `AEGIS_CONNECTOR_TOKEN`. Секреты Microsoft не сохраняются в Aegis. Приложению Entra требуется application permission `AuditLog.Read.All` и согласие администратора организации. Источник и требования: [Microsoft — List directoryAudits](https://learn.microsoft.com/en-us/graph/api/directoryaudit-list?view=graph-rest-1.0).

Первый запуск читает последний час, следующие — от контрольной точки с перекрытием пяти минут. Контрольная точка обновляется после подтверждения всех пакетов; дедупликация защищает от повторов. Чтение ограничено 50 страницами за запуск, при достижении лимита точка не продвигается. Агент читает журнал каталога Entra, не полный аудит Exchange, Teams или SharePoint. Периодичность задаётся системным планировщиком. Реальный tenant не проверялся: необходимы реквизиты вашей организации.
