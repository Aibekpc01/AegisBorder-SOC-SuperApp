# AegisBorder Supperapp — материал для защиты

## 1. Проект за 30 секунд

AegisBorder Supperapp — веб-система для обнаружения и расследования киберинцидентов и обучения сотрудников. Она собирает события в одном месте, объясняет, почему событие подозрительно, ведёт инцидент до решения и формирует отчёт. Работает в закрытой сети, на синтетических данных, решение всегда принимает человек.

## 2. Проблема

- События безопасности разбросаны по разным источникам: журналы входа, USB-устройства, файловые операции, почта, внешние средства защиты.
- Средства защиты часто сообщают «тревога», но не объясняют причину — оператору трудно принять обоснованное решение.
- Расследование ведётся в переписке и разрозненных файлах: теряется история, сложно доказать, кто и что сделал.
- Обучать новых сотрудников на реальных инцидентах нельзя — нужна безопасная среда.

## 3. Решение и практическая польза

| Для кого | Польза |
|---|---|
| Оператор | Единая лента событий, объяснение каждого срабатывания, доказательства и хронология в одной карточке |
| Руководитель | Статусы и ответственные по каждому случаю, журнал действий с проверкой целостности, PDF-отчёт в один шаг |
| Подразделение | 15 учебных сценариев атак, академия, режим демонстрации — подготовка без риска для реальных систем |

## 4. Основные возможности

1. Мониторинг событий с поиском, фильтрами и живым обновлением.
2. Детерминированные правила корреляции (например, «≥ 5 ошибок входа за 60 секунд») + модуль аномалий на scikit-learn.
3. Центр инцидентов: риск, статусы, ответственные, комментарии, граф связей.
4. Документы расследования: редактор, шаблоны, версии, согласование.
5. PDF-отчёты на русском языке.
6. Интеграции: API-приёмники для Kaspersky, DLP, Microsoft 365, импорт JSON/CSV.
7. Локальный DLP-агент для Windows.
8. 11 ролей с серверной проверкой иерархии.
9. Журнал действий с цепочкой подписей HMAC-SHA256.

## 5. Технологические преимущества

- **Закрытый контур.** Интерфейс не загружает ни одного внешнего ресурса; разворачивается одной командой `docker compose up`.
- **Безопасность по умолчанию.** Argon2, HttpOnly-cookie с SameSite=Strict, проверка Origin, лимиты попыток, строгая CSP, HSTS.
- **Объяснимость.** Правила детерминированы — можно показать, почему сработало предупреждение. Это важнее «чёрного ящика» для служебного применения.
- **Проверяемость.** 172 серверных и 32 клиентских автотеста, сквозные сценарии Playwright.
- **Производительность.** Главная загружается за 0,2–0,8 с, вес 256 КБ, сдвигов макета нет.

## 6. Архитектурные решения (что спросят разработчики)

| Решение | Почему |
|---|---|
| FastAPI + SQLAlchemy + PostgreSQL | Типизированные схемы (Pydantic), автоматическая OpenAPI-документация, надёжная СУБД; SQLite для быстрых тестов |
| React SPA, ленивые чанки | Главная и рабочее приложение грузятся отдельно; публичная страница не тянет код внутренних экранов |
| Сессия в HttpOnly-cookie, а не в localStorage | Скрипт на странице не может прочитать токен — XSS не крадёт сеанс |
| Детерминированные правила + отдельная ML-модель | Объяснимость для оператора; ML — только как дополнительный сигнал |
| HMAC-цепочка журнала | Изменение старой записи ломает подписи всех последующих — подмена видна |
| SVG-сцена вместо WebGL | Мгновенная отрисовка, работает на любом ПК и в закрытой сети |
| Дизайн-токены | Один источник цвета и размеров: две темы и единый вид всех экранов |

## 7. Интерфейс

- Единый визуальный язык «Цифровой рубеж»: линия границы с контрольными точками — образ назначения системы.
- Тёмная и светлая темы, контраст текста по WCAG AA.
- Простой режим с пояснениями для новичков и технический режим для специалистов.
- Полноценная мобильная и планшетная версии.
- Учтены `prefers-reduced-motion`, видимый фокус, управление с клавиатуры, `Ctrl K` для поиска.

## 8. Сценарий демонстрации (8–10 минут)

1. **Главная (1 мин).** Первый экран: сигналы идут к рубежу, консоль показывает путь «событие → правило → инцидент → отчёт». Прокрутить до «Технологии и надёжность».
2. **Вход (30 с).** `/app`, учётная запись комиссии. Показать проверку готовности сервера.
3. **Учебный сценарий (1,5 мин).** «Учебные сценарии» → «Неизвестное USB-устройство» → запуск. Подчеркнуть: события реально пишутся в базу, но в изолированном сеансе.
4. **События (1 мин).** «Мониторинг событий»: новые записи, поиск, карточка события.
5. **Инцидент (2 мин).** «Центр инцидентов»: риск и *объяснение причины*, назначить ответственного, комментарий, сменить статус.
6. **Документ и отчёт (1,5 мин).** Workspace: шаблон, автосохранение, версии. «Отчёты» → PDF.
7. **Контроль (1 мин).** «История действий» → проверка целостности журнала. «Пользователи и роли» — иерархия.
8. **Финал (30 с).** Светлая тема, телефонный вид (DevTools), итог: «от сигнала до решения — в одной системе».

Запасной вариант без сети и сервера: раздел «Демонстрация проекта» и учебный пример на главной работают без серверных действий.

## 9. Вопросы комиссии и ответы

**Это работает с реальными данными?**
Нет, и это сделано намеренно. Все события синтетические, реальные служебные системы не подключены. Архитектура готова к подключению: есть API-приёмники и агент, формат событий единый.

**Чем вы отличаетесь от готовых SIEM?**
Цель — не заменить промышленную SIEM, а дать понятный рабочий контур: объяснение каждого срабатывания, ведение расследования и документа, обучение на тех же экранах. Работает в закрытой сети без лицензий и внешних сервисов.

**Как обеспечена безопасность самой системы?**
Пароли — Argon2. Сеанс — в HttpOnly-cookie, недоступной скриптам; SameSite=Strict и проверка Origin защищают от CSRF. Лимиты попыток входа. Строгая Content-Security-Policy. Права проверяет сервер. Все действия пишутся в журнал с цепочкой подписей.

**Что будет, если администратор изменит запись журнала в базе?**
Каждая запись подписана вместе с подписью предыдущей. Проверка в «Истории действий» пересчитает цепочку и покажет место разрыва. Ключ подписи хранится вне базы (`AUDIT_KEY`).

**Почему правила, а не нейросеть?**
Оператор должен понимать, почему сработало предупреждение, и обосновать решение. Правила дают это объяснение. Модуль аномалий на ML есть, но как дополнительный сигнал, а не как единственный судья.

**Aegis AI — это ChatGPT?**
Нет. Языковая модель не подключена и данные никуда не отправляются. Помощник собирает описание из сохранённых фактов по шаблону.

**Как система масштабируется?**
Сервер без состояния, данные в PostgreSQL; можно запустить несколько экземпляров за обратным прокси. Ограничения: лимиты запросов сейчас хранятся в памяти процесса — для нескольких экземпляров их нужно вынести в общее хранилище (например, Redis).

**Как проверяли качество?**
172 серверных теста, 32 клиентских, сквозные сценарии Playwright, скриншоты на 5 ширинах экрана в двух темах, замер метрик загрузки. Результаты — `TEST_REPORT.md`.

**Почему на главной эмблемы ведомства — это официальный продукт?**
Нет. На главной и в подвале прямо указано: демонстрационный проект, не официальный сайт КНБ РК, официального одобрения не заявляется. Эмблемы отключаются одной настройкой сборки (`VITE_PUBLIC_OFFICIAL_EMBLEMS=false`).

**Что дальше?**
Обновить устаревшие сквозные тесты; перевести оставшиеся старые стили на токены; вынести лимиты запросов в общее хранилище; подключить реальный источник событий в пилотном контуре.
